## Additional findings, highest priority first

### 1. High — Markdown/AI-context silently lose media and transcripts

**Reproduced in supplied artifacts.** `markdown()` chooses text whenever `payload.text` is a string, including an empty string, then uses `else if` for assets. All seven screenshots and the audio block in this sample have `text: ""`, so assets and the transcript branch are skipped. The editor contributes to the problem: it registers the text-save callback for every block type and adds empty text to media blocks during save boundaries. Make media handling independent of text and register text editors only for text-based blocks. Images should also have image Markdown syntax when intended to display inline.

References: `src/main/services/export-service.ts:346`; `src/renderer/src/features/editor/PageWorkspace.tsx:465`.

### 2. High — The app produces lossless exports it cannot import

**Reproduced.** Exporting the second page, exporting the second note, or exporting a notebook after trashing its first note each causes import to throw `The archive has invalid hierarchy ordering.` Export preserves original positions and filters deleted records; validation requires every position group to be exactly 0..N-1. Scoped exports and deletion gaps violate that condition. Define a consistent contract for preserving versus normalizing positions; current tests even label a nonzero starting position invalid without testing that the exporter creates it.

References: `src/main/services/export-service.ts:86`, `:242`; `src/main/services/data-safety.test.ts:109`.

### 3. High — Duplicate blocks/notes lose their related graph

**Reproduced for an image block; confirmed in code for note copies.** Duplication copies block JSON but not `asset_references`, `block_sources`, relations or transcription ownership/history. A duplicate image still displays an asset ID but has no asset reference rows. After the original is trashed, a lossless export containing the duplicate has zero assets. Cleanup can also regard the still-visible image as unreferenced. Duplicate the relevant graph and remap run/block links rather than only copying rows.

References: `src/main/services/notebook-service.ts:587`, `:688`; `src/main/services/export-service.ts:282`.

### 4. High — Source captures are not atomic

**Reproduced with a deliberate database failure.** Rejecting the final `block_sources` insert during region capture leaves one new asset and one screenshot block. Text capture and Q&A creation likewise span multiple independently committed service calls. Failed operations can leave incomplete content, lose provenance or create duplicates on retry. Wrap the graph mutation in one transaction and clean up newly written files if it fails.

References: `src/main/services/notebook-service.ts:1694`, `:1713`, `:1749`. Recording already implements a safer transactional pattern at `:888`.

### 5. High — Windows asset import containment uses a POSIX separator

**Confirmed by Windows path semantics; Windows execution was not available.** Import computes native `resolve()` paths then tests `source.startsWith(root + '/')`. Windows resolves paths with backslashes, so normal archives containing assets fail this containment check. Use the existing portable containment helper or `path.relative()` with platform-aware checks.

Reference: `src/main/services/notebook-service.ts:1227`.

### 6. Medium — Screenshot source links are hidden

**Confirmed against all seven supplied screenshot blocks.** Region capture stores provenance in `block_sources`, but screenshot JSON contains no `sourceDocumentId`. The editor only offers View source and renders the provenance link when that JSON property exists. Thus the persisted provenance is inaccessible from these screenshot controls even though `getBlockSource()` could retrieve it. Gate source UI on actual provenance.

References: `src/renderer/src/features/editor/PageWorkspace.tsx:568`, `:609`, `:712`; `src/main/services/notebook-service.ts:1713`.

### 7. Medium — Printed-page provenance is discarded for regions; bounds depend on display scale

**Confirmed in code.** The Printed page field is forwarded for text/Q&A captures, but not region captures. Region bounds are stored in rendered canvas pixels, incorporating zoom/device scale, without storing that scale or converting to PDF coordinates. The screenshot bytes remain valid, but the rectangle cannot be consistently mapped back to a PDF page across display settings. Save printed-page metadata and canonical PDF coordinates.

References: `src/renderer/src/features/sources/SourceWorkspace.tsx:197`, `:612`; `src/main/services/notebook-service.ts:1746`.

### 8. Medium — Notebook exports can reorder pages

**Confirmed in code.** Notes are ordered by page UUID (`n.page_id`) rather than page position. Multi-page Markdown/PDF can follow UUID order instead of notebook order. Order notes by `p.position, n.position`. The supplied one-page sample cannot exhibit this.

Reference: `src/main/services/export-service.ts:253`.

### 9. Medium — Readable exports omit source citations and relation targets

**Confirmed in code.** Markdown/AI-context ignore `blockSources`, `sources` and `relations`; PDF also omits citations and semantic relationships. A copied source PDF is insufficient to identify which page supports a claim. Include source title, PDF/printed page and relevant block relations. Lossless JSON retains these records in the supplied sample.

References: `src/main/services/export-service.ts:189`, `:331`.

### 10. Medium — PDF render and asset package use separate snapshots

**Risk confirmed in code.** PDF markup is read before awaiting hidden-window rendering; `start()` then reads the database again to collect assets. Editing or deleting content during that await can produce a PDF representing one state and an asset package representing another. Render and publish from one immutable export read model.

References: `src/main/services/notebook-service.ts:344`; `src/main/services/export-service.ts:189`, `:113`.

### 11. Medium — Asset diagnostics misreport other notebooks and miss missing files in integrity jobs

**Reproduced.** `diagnoseAssets(notebookId)` scans the entire managed directory but builds its known-path set from only that notebook. An asset belonging to a second notebook appears as untracked. Separately, deleting a managed file then running the integrity job returns completed with an empty mismatch list because it only hashes files that exist. The synchronous diagnostic method always returns `hashMismatched: []`. Make scope consistent and report missing, untracked and mismatched assets separately.

References: `src/main/services/notebook-service.ts:1461`, `:365`.

### 12. Medium — Transcription quality has no review/correction path

**Observed in artifacts; cause not established by listening.** The Arabic Base-model transcript has questionable words and repeated ending phrases while status is completed and confidence is null. The adapter accepts the sidecar output; the UI displays it as a small text string, without a transcript editor or usable segment review. Preserve the raw result, allow a reviewed correction, and assess larger multilingual models/VAD using actual Egyptian Arabic recordings. Do not silently delete repeated text: repetition may sometimes be spoken.

References: `src/main/services/transcription-service.ts:349`; `src/renderer/src/features/editor/PageWorkspace.tsx:1177`.

### 13. Medium — Cancelling queued transcription can leave the run stuck queued; restart can leave it running

**Confirmed in code.** Job cancellation updates the jobs table, but the queued transcription run is only updated when its handler executes. A cancelled queued job never executes. Startup marks running jobs failed but does not reconcile `transcription_runs`. The audio panel polls queued/running run state, so it can keep polling a run with no active worker. Reconcile both records together.

References: `src/main/services/job-service.ts:63`, `:97`; `src/renderer/src/features/editor/PageWorkspace.tsx:1179`.

### 14. Medium — Whisper termination escalation is incorrect

**Conditional risk confirmed in code.** The delayed SIGKILL is guarded by `!child.killed`; that property reflects whether a signal was sent, not whether the process exited. A successful SIGTERM sets it even if the process ignores termination. Such a worker can keep the job and normal close waiting. Track process exit and clear escalation timers on close.

Reference: `src/main/services/transcription-service.ts:323`; `src/main/services/notebook-service.ts:412`.

### 15. Medium — Large model downloads require several GB of main-process memory

**Confirmed allocation pattern; no multi-GB download performed.** Download accumulates chunks and then concatenates the whole model. Large-v3 is roughly 3.1 GB, so peak allocation includes the retained chunks plus another full model buffer. Cancellation also cannot abort a pending fetch/read because no abort signal is supplied. Stream to a temporary file, hash incrementally, and abort the network stream on cancellation.

Reference: `src/main/services/transcription-service.ts:155`.

### 16. Medium — OpenRouter credentials are persisted as plaintext

**Confirmed storage implementation; no real credential accessed.** The key is written into `config/transcription.json`; POSIX 0600 reduces access but is not OS-backed encrypted credential storage. This differs from the intended secure-storage direction in README. Use Electron/OS credential encryption and preserve the current exclusion from notebook exports.

Reference: `src/main/services/transcription-service.ts:544`, `:577`.

### 17. Medium — Regular notebook IPC does not validate sender/frame

**Confirmed in code; no exploit attempted.** Lifecycle IPC validates the sender and main frame, but normal notebook endpoints discard `_event` and only validate payloads. Apply a shared sender/frame guard consistently. Existing renderer sandboxing and denied navigation remain useful protections.

Reference: `src/main/ipc/register-notebook-ipc.ts:109`; compare `src/main/index.ts` lifecycle handlers.

### 18. Medium — Renderer failure can leave normal close waiting forever

**Conditional risk confirmed in code.** Close is prevented pending a renderer save acknowledgement. Renderer process loss is logged but provides no failed-handshake recovery, timeout or relaunch/close choice. A crashed renderer cannot acknowledge. Offer an explicit recovery route that makes unsaved-state consequences clear.

Reference: `src/main/index.ts:58`.

### 19. Low — PDF metadata exposes the entire generated HTML/data URL

**Observed using pdfinfo on the supplied PDF.** There is no HTML title, so Chromium uses the large data URL, including encoded note text and image data, as the PDF title. Set a short escaped notebook title before printing. The supplied PDF is also untagged and defaults to Letter; assess tagged output and explicit paper size if accessible/shareable reports are required.

Reference: `src/main/services/pdf-renderer.ts:19`.

### 20. Low — Successful Whisper sidecar files are never removed

**Confirmed in code.** Failure removes the temporary .txt/.json files; success reads them then returns without removal. Every completed run leaves derived files beside the WAV, adding disk usage and diagnostic clutter. Clean them in a finally block after retaining results in SQLite.

Reference: `src/main/services/transcription-service.ts:337`, `:349`.

### 21. Low — Export UI confirms queueing rather than completion

**Confirmed in code.** ExportDialog closes as soon as `exports.start()` returns a job. It provides no completion result, output-directory action or immediate failure notice. Users must discover Jobs to inspect eventual results. Also distinguish user picker cancellation from operational failure; export/backup cancellation currently throws and creates an error record.

References: `src/renderer/src/App.tsx:1330`; `src/main/ipc/register-notebook-ipc.ts` export/backup handlers.

### 22. Low — Markdown content is emitted without structural escaping

**Confirmed in code.** User titles/text are interpolated directly into Markdown. Embedded headings, links or other Markdown syntax can unintentionally change exported structure. Define whether block text is intended as raw Markdown; escape titles and literal text accordingly.

Reference: `src/main/services/export-service.ts:341`.

## Practical PDF extraction improvements

1. Separate actual selected text from the optional whole-page extraction preview. Do not call the whole page a selection.
2. Rebuild lines using PDF.js `hasEOL`, position transforms and direction metadata; keep Arabic logical text intact rather than manually reversing strings. Handle columns and tables separately.
3. Add region-based text extraction so users can exclude margins, sidebars and neighboring columns.
4. Use the supplied Arabic PDF as a regression fixture, with expected reading order, mixed English terms, bullets and table rows. Compare PDF.js and a layout-aware extractor before adopting another engine.
5. Offer Arabic/English OCR as an explicit fallback for broken font mappings or image-only content; keep the screenshot and original source provenance alongside editable extracted text.

The official [PDF.js TextItem documentation](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html) describes direction, transform and end-of-line metadata. The official [whisper.cpp VAD example](https://github.com/ggml-org/whisper.cpp/blob/master/examples/vad-speech-segments/README.md) provides a basis for testing speech segmentation. These are implementation options, not claims of measured recognition/OCR improvement in this review.
