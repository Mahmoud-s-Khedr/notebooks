# Extraction and transcription: implemented behavior and future options

The October 2026 repair keeps PDF.js and the existing Whisper/OpenRouter providers. No OCR engine, alternative PDF engine, or VAD stage was added. Recognition quality has not been benchmarked on Egyptian Arabic speech; completion means the engine returned a result, not that the words are correct.

## Current behavior

PDF text uses item geometry to group baselines, detect persistent gutters between prose columns, separate table cells with tabs, and retain PDF.js logical Arabic strings. Selection remains distinct from **Extract page text**. **Extract region text** filters intersecting items in the selected rectangle. Review extraction before capture: geometry heuristics can misclassify layouts, and bad font mappings still produce bad text. Rotated/vertical text and complex tables need additional evaluation. [PDF.js documents the item's direction, transform and line-break metadata](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html).

New screenshot regions retain PDF points with a bottom-left origin and `coordinateSpace: "pdf-points-bottom-left"`, including printed-page provenance. Untagged older regions remain legacy rendered pixels; they are never treated as canonical PDF coordinates. Their screenshot and source/page link remain usable.

Completed audio runs keep immutable recognition text and original timestamped segments. Reviewed text is stored separately on the audio block, keyed by the exact run ID. Display and readable exports prefer it. Lossless exports retain both forms. Edits never receive fabricated segment times or confidence values. Segment playback refers to the original recognition, even when the reviewed wording differs.

## Larger multilingual models and VAD

The app already lists multilingual Tiny, Base, Small, Medium and Large-v3 downloads. The pinned artifact sizes in this repository are approximately 78 MB, 148 MB, 488 MB, 1.53 GB and 3.10 GB. Storage size is not peak memory use. A bigger model is an evaluation option; this project makes no claim that it improves any particular recording. Downloads stream to a temporary file with incremental checksum verification and abortable reads. Local inference still requires the separately packaged Whisper runtime. [whisper.cpp's upstream implementation and model documentation](https://github.com/ggml-org/whisper.cpp/blob/master/README.md).

VAD could trim/segment non-speech before transcription. It would require a separately versioned detector model, threshold controls, correct timestamp offsets, cancellation and cleanup integration. Measure speech lost at clip boundaries, hallucinations during silence, repeated phrases, latency and peak memory. Preserve the original WAV. Do not automatically remove repeated words: the speaker may have repeated them. [whisper.cpp's VAD example](https://github.com/ggml-org/whisper.cpp/blob/master/examples/vad-speech-segments/README.md). Audit the engine and detector/model licenses separately before shipping.

An evaluation set should include consented Egyptian Arabic recordings with English technical terms, silence, background noise and different microphones. Have fluent reviewers produce reference transcripts, report word/character errors and timing accuracy, and measure runtime/memory on the target Linux and Windows machines. Compare Base/Small/Medium/Large-v3 on the same inputs, with and without VAD, before choosing defaults. Fresh speech evaluation and physical-device testing remain outstanding.
